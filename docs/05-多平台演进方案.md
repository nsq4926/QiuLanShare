# 05 · 多平台决策与路线

> 记录"为什么这样做"和"现在走到哪"。实现细节看 `01`，进度看 `08`，功能对照看 `13`。
> 最后核对：2026-11-21。

## 一、结论先行

1. **全对等 P2P**：每个原生端都含服务端 + 发现 + 出站客户端，手机↔手机直连，PC 关机不影响手机互通。
2. **不上云**：没有中转、没有账号、没有跨网漫游。离线消息**不做队列**——直接失败并给原因，宁可"没发出去"，不制造"假已发送"。
3. **只有四个端**：Windows 插件（主）、Windows exe（托盘版）、鸿蒙、Android。浏览器**永远只是客户端**。
4. **已取消**：Edge 扩展、鸿蒙 4 原生端、iOS 原生端、中心服务器。

## 二、决策表

| # | 决策 | 影响 / 落到哪 |
|---|---|---|
| U1 | `deviceId`（随机 UUID）作主键，MAC 只作可见标识与"同一台机器"的辅助证据 | 换网卡/随机 MAC 不产生新设备；MAC 缺失显示「未获取」 |
| U2 | 全对等（推翻"协议对等、落地中枢"） | 每端都要服务端；消息模型为"各端自增 seq + 幂等去重" |
| U3 | 发现只由原生端做；网页向已连的原生端要 `/api/devices` | 浏览器不做扫描、不能当服务端 |
| U4 | 鸿蒙 4 取消；非 NEXT 的鸿蒙 4 用户由 **Android apk** 覆盖 | 不维护 `@ohos.*` 子集与例外表 |
| U5 | iOS 不纳入；最多"浏览器访问"顺带兼容 | 不排期 |
| U6 | 不上云 | 无中转、无漫游；离线不做队列 |
| U7 | Edge 扩展取消；Android 提前为 P4 | 阶段顺序：P0 → P1 → P2 → P3 → P4 |

## 四、五个对等难点的结论

| 难点 | 结论 | 实现位置 |
|---|---|---|
| **手机后台被冻结 → 不可达** | 鸿蒙用 `backgroundTaskManager` 长时任务（dataTransfer），实测后台/熄屏 ~10 分钟后被回收；Android 用前台服务可长期常驻。**"对端在线"是 P2P 硬前提**，产品文案要直说"对方暂时连不到你，但你仍可主动发" | `Node.syncKeepAlive()` / `NodeService` |
| **端口与双实例** | 端口 8765→8767 递进，TCP 必须 `SO_EXCLUSIVEADDRUSE`（否则递进是假的）；UDP 必须 `SO_REUSEADDR`（同机双实例都要收广播）；同机双实例是两个 `deviceId`，**不合并** | `HttpServer.cpp` / `HttpSrv.ets·kt` |
| **消息顺序与去重** | `msgId = deviceId:epoch:seq`，`seq` **本端全局单调**（不是每会话从 1）；`epoch` 解决"清空后 seq 归零导致永久拉不到"；排序用 `(peerTs, seq)` 不用 `recvTs` | `Proto` / `Hub` |
| **离线消息** | 不做队列、不自动重投；失败只两种原因，留一条「未发送」可点重发 | `deliverText/File` |
| **Windows 防火墙拦入站** | 只做三件事：如实回报、加缺失规则、记住"不再提示"。**不静默加、不提权、不删规则** | `Firewall.cpp` |

补充两条被验证过的细节：

- **`seq` 跳号是设计**：单个对端看到的 seq 不连续（1、3、7），**不得据此推断丢包**。
- **`/api/hello` 与 announce 的 `ip/mac` 必须取自过滤后的网卡集合**，不能用"带默认路由的网卡"（VPN 隧道会把 `10.20.0.1` 当 LAN 地址报出去）。

## 六、明确不做（下一个人别再加）

| 不做 | 原因 |
|---|---|
| 云端中转 / 账号体系 | U6；局域网工具，多一个云就多一份运维与隐私责任 |
| 离线发送队列 / 自动重投 | 在线判定本身不准，队列必然长期 pending → "假已发送" |
| 消息撤回 / 编辑 | 需求未提；需要新的消息版本语义 |
| 群聊 | 会话模型是两方 `convId`，扩群要重做身份与投递 |
| 端到端加密 / 鉴权 | 当前定位是可信局域网；要加先定密钥分发 |
| 跨网段 / 公网直连 | 广播发现失效，需要引入中继或手动端口映射 |

## 七、已知风险

| 风险 | 说明 |
|---|---|
| 国产 ROM 杀后台 | Android 前台服务也可能被杀，需引导加白名单；鸿蒙 10 分钟上限是系统限制 |
| 双真网卡合并未验 | 本机只有一张真网卡，属环境不满足（17a） |
| 无鉴权 | 同网段任何人知道 `IP:port` 就能读消息与文件 |
| 移动端无消息条数上限 | 只有 Windows 有 500 条上限；移动端随历史文件增长，靠保留期清理 |
