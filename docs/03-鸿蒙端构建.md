# 03 · 移动端构建（鸿蒙 / Android）

> 本文覆盖两个移动端的构建、签名、装机与日志。协议见 `01`，脚本清单见 `12`。
> 关键前提：**移动端改动必须装真机验证**。静态检查全绿也可能跑不起来——本项目多数 bug 是"静默失败"。

## 一、鸿蒙（ArkTS / API 20 兼容，真机 API 26）

### 1.1 环境与工程

| 项 | 值 |
|---|---|
| 工程 | `harmony\`（DevEco 工程，包名 `com.sanqiu.TrafficMonitorLanShare`） |
| 兼容/目标 SDK | `compatibleSdkVersion` / `targetSdkVersion` = `6.0.0(20)`，本地 SDK API 26 可编 |
| 设备类型 | phone / tablet；`backgroundModes: ["dataTransfer"]` |
| 权限 | `INTERNET`、`GET_NETWORK_INFO`、`KEEP_BACKGROUND_RUNNING` |

### 1.2 构建与安装

```bash
# 静态检查（0 error 才算过）
tools\arkts.ps1
# 或直接：cd harmony && devecocli check arkts

# 构建（产物在 harmony\entry\build\default\outputs\default\）
cd harmony && devecocli build --modules entry --build-mode debug

# 装机 + 启动（真机）
hdc install -r harmony/entry/build/default/outputs/default/entry-default-signed.hap
hdc shell aa start -a EntryAbility -b com.sanqiu.TrafficMonitorLanShare
```

`tools\deveco.ps1 build|release|run -Device <serial>|check|log` 是封装入口；
`deveco.ps1 run` 会串起"构建 → 装机 → 启动 → 冒烟"。

### 1.3 签名（最容易卡住的一步）

- HarmonyOS NEXT **不信任侧载的 release 渠道应用**（报 `9568322`）→ 一律用 **debug 签名**。
- 生成：`devecocli auth login --no-prompt` → `devecocli signature generate --type debug --force`
  （会把 profile 写回 `harmony/build-profile.json5`）。
- **profile 绑设备 UDID**：换手机必须重新生成。
- 华为 p12 报"口令错"多半是**格式非标**，不是口令错（hvigor 能解）。
- `devecocli` 走本机代理会报 `Invalid proxy authorization` → 先跑 `tools\devecocli-noproxy.ps1`。
- **上架包用另一条签名**：`harmony/build-profile.json5` 里 `signingConfigs.release` + `products.appgallery`
  指向仓库根目录的 AGC 发布材料（`TrafficMonitorLanShare.p12` / `...Release.p7b` / `.cer`，2026-11-08 申请，
  有效期到 2029-11-08）。打上架包：
  `hvigorw --mode module -p product=appgallery -p module=entry@default -p buildMode=release assembleHap --no-daemon`
  产物在 `entry/build/appgallery/outputs/default/entry-default-signed.hap`，**别装真机**（release 渠道侧载报 9568322）。
- 签名材料换人接手时先自检：
  `java -jar <SDK>\default\openharmony\toolchains\lib\hap-sign-tool.jar verify-app -inFile <hap> -outCertChain out.cer -outProfile out.p7b`，
  必须打印 `verify: Verify success`，且证书链叶子是 AGC 上那张发布证书。

### 1.4 常用设备命令

```bash
hdc list targets                       # 设备列表（IP:port 形式也算在线）
hdc shell power-shell wakeup            # 锁屏时先唤醒，否则 aa start 报 The device screen is locked
hdc shell snapshot_display -f /data/local/tmp/s.jpeg && hdc file recv /data/local/tmp/s.jpeg s.jpeg
hdc shell "hilog -x | grep -i lanshare" # 应用日志（DOMAIN=0x9527, TAG=LanShare）
```

> Git Bash 下必须 `export MSYS_NO_PATHCONV=1`，否则路径被转换、截图失败；截图后缀必须 `.jpeg`。
> `hdc file recv` 的本地路径要写**相对路径**（写绝对路径会被拼到当前目录后面）。

### 1.5 鸿蒙端结构

| 模块 | 职责 |
|---|---|
| `common/Proto.ets` | 常量、FNV-1a64 `convId`、`msgId`、五态、JSON 取值/转义 |
| `common/Types.ets` | 数据模型（字段与 Windows 落盘 JSON 逐字一致） |
| `common/Hub.ets` | 设备表、消息、会话、未读、`histRev`、MAC 合并 |
| `common/HttpSrv.ets` | `TCPSocketServer` + 手写 HTTP/1.1 子集 |
| `common/Api.ets` | 19 个 `/api/*`（含分片续传） |
| `common/Disc.ets` `common/Peer.ets` | UDP 发现、出站投递 |
| `common/Store.ets` `common/SaveOut.ets` `common/Settings.ets` | 存储、系统保存、设置（单一写入者） |
| `common/Transfer.ets` `common/Notify.ets` | 传输任务表、系统通知 |
| `common/Node.ets` `common/App.ets` | 装配启停、健康探测、长时任务、全局单例 |
| `common/UiTokens.ets` + `Settings.ets` 的 `LsPalette` | 设计令牌与配色（规范见 `UI Design.md`） |
| `pages/Index.ets` | 主界面（抽屉 / 聊天 / 传输抽屉 / 设置 / 看图，单文件） |

## 二、Android（Kotlin / Compose）

### 2.1 环境与工程

| 项 | 值 |
|---|---|
| 工程 | `android\`（AGP 8.13.2 + Kotlin 2.2.21 + Compose BOM 2025.12.01） |
| SDK | `D:\APP\AndroidStudioSDK`（compileSdk 36 / targetSdk 36 / minSdk 23） |
| 工具链 | Gradle 8.13 + **JDK 21**（`D:\APP\AndroidToolchain`） |
| 包名 | `com.sanqiu.lanshare`（`MainActivity` + `net.NodeService` 前台服务） |

> AS 自带的 JBR 25 对 Gradle 8.x 太新，必须用 JDK 21。

### 2.2 构建 / 安装 / 测试

```powershell
tools\android-build.ps1 build       # assembleDebug → android\app\build\outputs\apk\debug\app-debug.apk
tools\android-build.ps1 test        # 单元测试（89 条）
tools\android-build.ps1 install     # 安装并启动到已连接设备
tools\android-device.ps1 -Serial <sn> -Action info|install|start|shot
```

- `curl` 访问 `dl.google.com` 报"吊销检查离线"是**假失败**，加 `--ssl-no-revoke`。
- Gradle 必须清空代理变量（脚本已做）。
- OPPO/ColorOS 用 `adb install` 会报 `Failure [-99]`（系统安装器收到广播后秒关自己）→
  `android-device.ps1 install` 已自动回退到 `pm install-create/write/commit` session API。

### 2.3 启动与调试

```bash
# 正式：用户在桌面点图标；服务由 UI 启动
# 自动化：带 autostart 直接拉起前台服务
adb shell am start -n com.sanqiu.lanshare/.MainActivity --ez autostart true
adb logcat -d -t 300 | grep -iE "AndroidRuntime|sanqiu"
adb exec-out screencap -p > shot.png
```

> 屏幕尺寸与点击坐标：`wm size` 是物理分辨率，`screencap` 可能被缩放
> （例：MatePad 物理 1600×2560，截图 1080×675）→ **点击坐标 = 截图坐标 × 2.37**。

### 2.4 Android 端结构

| 模块 | 职责 |
|---|---|
| `core/Proto.kt` `core/Types.kt` `core/Hub.kt` `core/Store.kt` `core/Settings.kt` | 与鸿蒙同构的协议与状态机 |
| `net/HttpSrv.kt` `api/Api.kt` | 服务端与 18 个 `/api/*` |
| `net/Disc.kt` `net/Announce.kt` `net/Peer.kt` | 发现与出站 |
| `net/Node.kt` `net/NodeService.kt` `net/NodeState.kt` | 装配、前台服务、UI 快照 |
| `net/Transfer.kt` `net/Notify.kt` | 传输任务表、通知 |
| `net/MediaExport.kt` | 收到图片/文件导出到相册/下载 |
| `ui/AppScreen.kt` `ui/ChatArea.kt` `ui/DeviceDrawer.kt` `ui/SettingsScreen.kt` | 界面（Compose） |
| `ui/components/LsComponents.kt` `ui/theme/LsTheme.kt` | 设计令牌与通用组件 |

**Compose 特有坑**：读外部可变对象要用"每秒整取快照"（`mutableStateOf` 整体替换），
只递增 tick 不会重跑读值分支 → 表现为"服务在跑、界面说没跑"。

## 三、两端的联调验证（最短路径）

```bash
# 手机自报（把 <ip> 换成设备 IP，端口以 hello 返回为准）
curl -s --noproxy "*" http://<ip>:8765/api/hello
curl -s --noproxy "*" http://<ip>:8765/api/devices

# 从电脑往手机发一条消息（走手机自己的出站通道）
curl -s --noproxy "*" -X POST -H "Content-Type: application/json" -H "X-Device-Id: pc-test" \
  -d '{"text":"ping","dir":"out","peer":"<手机 deviceId>"}' http://192.168.8.72:8765/api/message

# 分片上传（3 片，每片 1 MB）
curl -s --noproxy "*" -X POST --data-binary @c1 -H "Expect:" -H "X-Device-Id: pc-test" \
  "http://<ip>:8765/api/upload?name=big.bin&dir=in&peer=pc-test&xid=t1&offset=0&total=3145728"
```

查消息必须带 `X-Device-Id`，否则走 legacy 通道、过滤后为空（看起来像"没有消息"）。
