## 一、形态与拓扑

三端**都是对等节点**：各自跑 HTTP 服务端 + UDP 发现 + 出站客户端，没有中心服务器，也不上云。

```
Windows                                  HarmonyOS / Android
TrafficMonitor.exe                       App 进程
 └─ lanshare.dll（插件）                  ├─ HTTP/1.1 服务端（自实现，非框架）
     ├─ 任务栏两项 + 托盘                  ├─ UDP 发现
     ├─ HTTP 服务端  8765→8767            ├─ 出站客户端
     ├─ UDP 发现     8766                 ├─ 本地存储（jsonl）
     └─ 出站客户端                         └─ 原生 UI（ArkUI / Compose）
浏览器 ⇄ http://<ip>:<port>/              （手机也能内置网页，但 UI 不以网页为主）
```

| 端 | 产物 | 语言/框架 | 服务端实现 |
|---|---|---|---|
| Windows | `plugins\lanshare.dll`（必需）+ `LanShare.exe`（可选，托盘版） | C++17 / Win32 | `HttpServer.cpp`（socket + 手写 HTTP/1.1） |
| 鸿蒙 | `entry-default-signed.hap` | ArkTS / ArkUI | `common/HttpSrv.ets`（`TCPSocketServer` + 手写 HTTP/1.1） |
| Android | `app-debug.apk` | Kotlin / Compose | `net/HttpSrv.kt`（`ServerSocket` + 手写 HTTP/1.1） |

三个服务端都**只支持本项目用到的子集**：GET/POST、`Content-Length` 定长体、`Connection: close`（一连接一请求）、无 chunked 编码、无 keep-alive。

**三种身份严格分开**：

| 身份 | 键 | 进设备表 |
|---|---|---|
| 设备 | `deviceId` = `<平台前缀>-<12hex>`（`pc-` / `hm-` / `an-`） | ✅ |
| 网页 | `localStorage` 的 `web-<12hex>`，随 `X-Device-Id` 带 | ❌ 只标记可达 |
| 旧客户端 | `legacy:<设备名>` | ❌ 只有会话 |

## 二、身份、会话、消息（不可推翻）

1. **`deviceId`** 首次运行随机生成并落盘，**禁止**由 MAC/主机名/硬件派生（换网卡、随机 MAC、克隆镜像都会失效）。
2. **`convId`** = 两方 `deviceId` 排序后 FNV-1a **64 位**哈希，形如 `c-<16hex>`，**不含 IP**。
   - ⚠️ **offset basis = `1469598103934665603`**（比标准值少一位）。三端必须逐位一致，否则同一对设备裂成两个会话，症状是"消息偶尔不显示"且不报错。
   - 启动时用 3 组向量自检（`convIdSelfCheck()`），失败只告警、不阻断启动。
3. **`msgId = <deviceId>:<epoch>:<seq>`**；legacy 消息为 `legacy:<对端键>:0:<id>`。
4. **`seq` 本端全局单调**（不是每会话从 1 开始），`epoch` 在"清空历史"时递增。
   - 代价一：单个对端看到的 `seq` **不连续** —— 不得用"seq 连续"推断丢包。
   - 代价二：对端可从跳号幅度推断你给别的设备发过多少条 —— 已知并接受。
5. **`epoch`**：清空某会话 +1；清空全部只 +1 一次；按天裁剪不动。必须落盘。
6. **`histRev`**：消息集合真变了才 +1；客户端见变大 → 丢弃本地、全量重拉。

**消息字段**（`docs/13` 有完整列表）：

| 字段 | 约束 |
|---|---|
| `dir` | **绝对方向**：`in` = 对端发来，`out` = 本端发出。任何平台都按这个填，界面再按"自己是哪端"翻转 |
| `kind` | `text` / `image` / `file` / `system`（`system` 仅用于"记录已清空"提示） |
| `status` | 只有 `sent` / `failed`，**必须由真实投递结果给出**，不许默认 `sent` |
| 排序 | `(peerTs, seq, id)`；**不能用 `recvTs`**（补拉时它全是"现在"） |
| 幂等 | 同 `msgId` 重复提交不重复入库、不重复落文件；**重发会真的再投一次**并更新状态 |

## 三、发现与在线状态

**UDP 8766** 广播 `announce`，字段（三端逐字一致）：

```
v / app("TMLS") / deviceId / name / port / mac / ips[] /
acceptsInbound / filteredNicCount / apiVersion / resumable / platform
```

- `platform`：`windows` / `harmony` / `android`（Windows 端不写该字段，缺省记为 windows）。
- 收到 announce **立即单播回源一发**（2 秒限流），避免"广播丢一次就要等下一轮"。
- **两个独立开关**（设置页）：
  - **主动发现**：每 `discoverSeconds`（默认 10，可选 5/10/30/60）发一次广播，并登记收到的 announce。关掉后不再广播、不再登记新设备。
  - **被发现**：`acceptsInbound`。关掉后不再自报家门、不回应别人、对端列表里看不到本机；已建立的会话仍可主动发消息过去。
- 端口递进 `8765 → 8766 → 8767`；**实际端口以 announce/hello 报的值为准**，任何一方不得硬编码 8765。

**五态由服务端计算，客户端只渲染**（1:1 对应标签）：

| 值 | 判定 | 标签 |
|---|---|---|
| `online` | `now-lastReachableAt ≤ 30s` 且 `acceptsInbound` | 在线 |
| `online_no_inbound` | 同上但 `acceptsInbound=false` | 在线 · 不接收 |
| `unreachable` | 未达 online，但 `now-lastSeen ≤ 120s` | 暂时连不上 |
| `discovered` | 发现过但从未通信成功（`lastReachableAt==0`），且在 120s 内 | 已发现 |
| `offline` | 其余 | 离线 |

- **不变式 `onlineTtl(30s) < staleTtl(120s)`**，两个值随 `/api/hello` 下发，供断言读运行期常量。
- 冷启动一律把 `lastReachableAt` 视作 0（磁盘旧值只供排障），否则开机第一屏全是"在线"。
- 设备行 IP 选择：① 5 分钟内 `lastOkAt` 的 IP → ② 与本机同网段 → ③ `ips[]` 首项。**不得用设备级 `lastSeen` 推"哪个 IP 最近通"**。
- **发送候选不剔 TTL**（`sendCandidates`），**展示才剔**（`displayIps`）。混用会导致"一离线就再也发不出去"。

## 四、HTTP 契约

| 方法 | 路径 | 关键参数 | 说明 | 三端 |
|---|---|---|---|---|
| GET | `/` `/index.html` | — | 内置网页 | W/H/A |
| GET | `/api/ping` | — | `{ok:true}` | W/H/A |
| GET | `/api/hello` | — | 本机画像（见下） | W/H/A |
| GET | `/api/devices` | `limit` | 设备行；`/api/discover` 为只读别名 | W/H/A |
| GET | `/api/conversations` | — | 会话列表 | W/H/A |
| GET | `/api/messages` | `since` `wait`(≤25) `peer` `sinceEpoch` `sinceSeq` | 拉消息；`peer` 空=不过滤 | W/H/A |
| POST | `/api/message` | `{text,dir,peer,msgId?}` | 发文字，返回 `{ok,id,msgId,status,reason}` | W/H/A |
| POST | `/api/messages/read` | `{convId}` 或 `{peer}` | **未读清零唯一入口** | W/H/A |
| POST | `/api/upload` | `name,mime,dir,peer,msgId` / `xid,offset,total` | 发文件（整份或分片） | W/H/A |
| GET | `/api/upload/status` | `xid` | 续传前问已收字节 | W/H/A |
| GET | `/api/file` | `id` `inline=1` | 取文件 | W/H/A |
| GET | `/api/transfer` | — | 传输进度列表（**保留历史**，见第五节） | W/H/A |
| POST | `/api/transfer/remove` | `id` `mode=cancel\|remove` `all=1` | 取消在传 / 删除记录 / 清空传输列表 | W |
| POST | `/api/history/clear` | `convId` / `dev` / 无 | 清历史（**不删文件**） | W/H/A |
| POST | `/api/history/settings` | `days` | 保留天数（0=永不） | W/H/A |
| POST | `/api/devices/add` | `ip` `port` | 手动添加（探活并核对 deviceId） | W/H/A |
| POST | `/api/devices/remove` | `deviceId` `dry` `files` | 删除设备（先 `dry=1` 看路径/数量/大小） | W/H/A |
| POST | `/api/devices/rename` | `deviceId` `alias` | 改别名 | W/H/A |
| GET | `/api/firewall` | — | 能力位；鸿蒙/Android 如实回"系统不拦截" | W/H/A |
| GET/POST | `/api/discovery` | `{active,discoverable,seconds}` | 读/写发现策略：**主动发现**、**被发现**、广播周期（3–300 秒） | W |
| POST | `/api/firewall/allow` | — | 一键放行（仅 Windows） | W |
| POST | `/api/firewall/never` | — | 不再提示（仅 Windows） | W |
| POST | `/api/settings/save-dir` | `action=choose\|open\|set` | 换保存目录（仅 Windows） | W |
| POST | `/api/autostart` | — | 开机自启（仅 exe 版） | W |

`/api/hello` 响应（旧客户端忽略多余字段，纯增量）：

```json
{"app":"LanShare","name":"SANQIU","ip":"192.168.8.5","port":8765,"version":"1.1","device":"pc",
 "deviceId":"pc-...","mac":"B0:25:...","apiVersion":"2","resumable":true,"platform":"windows",
 "acceptsInbound":true,"filteredNicCount":0,"onlineTtl":30000,"staleTtl":120000,
 "epoch":3,"instance":"default","peer":"","historyDays":0,"saveDir":"D:\\TMShare",
 "activeDiscover":true,"discoverSeconds":3}
```

错误响应统一 `{ok:false,error:"..."}`，状态码诚实：`400` 参数 / `404` 无此物 / `405` 方法 /
`409` 续传偏移不符 / `413` 太大 / `500` 异常 / `502` 对端不可达 / `503` 未初始化或并发超限。

`/api/discovery`（仅 Windows）语义：`GET` 返回当前值，`POST {"active","discoverable","seconds"}`
写入并**立即生效**（同时回写 `lanshare.ini` 的 `[discovery]` 段）。`active=false` → 不再周期广播、
不再登记新设备；`discoverable=false` → announce 里 `acceptsInbound=false` 且不再自报家门。
两项都关等于"只听不发"。移动端由设置页本地生效（同一语义，不经过该端点）。

**legacy 分流只看一个条件**：请求是否带 `X-Device-Id`。不带 → legacy 通道（按 `legacy:*` 前缀过滤，不下发 `system` 消息）。**不得**按 convId 判断。

## 五、文件与传输入协议

**整份上传**

```
POST /api/upload?name=&mime=&dir=&peer=&msgId=   body=原始二进制（非 multipart）
   → <saveDir>/<设备名>-<deviceId>/<原名>（内容去重、同名加 (2)）
   → 生成 kind=image|file 的消息，返回 fileId
GET /api/file?id=<fileId>&inline=1   取回
```

**分片 / 断点续传（v2.1）**

```
POST /api/upload?…&xid=<id>&offset=<n>&total=<n>&msgId=   body=这一片（1 MB）
   200 {"ok":true,"partial":true,"received":n}            → 继续
   200 {"ok":true,"received":total,"message":{…}}         → 收齐并入库
   409 {"ok":false,"error":"offset_mismatch","received":n} → 从 n 续传
GET  /api/upload/status?xid=<id> → {"ok":true,"received":n}
```

- `.part` 落在对端 `saveDir/.~<xid>.part`，**收满 `total` 才入库**（不会出现半截文件）。
- 能力协商：`/api/hello` 与 announce 带 `"resumable":true`；没有该字段的对端走整份上传。
  **三端自带的客户端都按 1 MB 分片**（Windows 出站也是，见 `08` 第九节：整份 POST 等于让手机端
  把大文件整个塞进内存，会被 FreezeDetector 判 THREAD_BLOCK_6S 杀掉）。
- 校验三条：`total` 上限（4 GB，三端同源）、`offset` 必须等于已收长度、
  `xid` 只允许 `[A-Za-z0-9_-]`（会进文件名，防路径穿越）。
- 失败时先问 `status` 再续传；`msgId` 不变 → 幂等只留一条。
- 内容去重：同目录内"尺寸 + FNV-64"相同即复用已有文件，不加 `(2)`；`.~*.part` 不参与去重。

**传输进度**：`GET /api/transfer` → `items[{name,dir,total,received,speed,status,peer}]`；
**整份上传也登记一条传输记录**（不能只有分片才出现在列表里）；界面只显示**当前会话对端**的记录。
界面与通知栏共用一个内存表（`Transfer.ets` / `Transfer.kt` / `TransferHub::TransfersJson`），
速度按 200 ms 采样平滑。**续传队列只在内存**，进程被杀后从 0 重传（幂等保证不重复上屏）。

**单份上限 = 4 GB**（三端同一常量；收发都是流式，不再整份读进内存）。

**分片大小 = 1 MB**（三端同一常量）。256 KB 时每片都要新建一条 TCP 连接（本项目
`Connection: close`），10 MB 实测只有 1 MB 片的 1/3～1/2 速度；见 `08` 第九节的实测表。

**传输列表保留历史**（v2.2 起，且**落盘**）：
- 一条记录有终态：`active / done / failed / cancelled`，**完成后不自动消失**，新的在上；
- 用户点 ✕：在传 → 取消（`cancelled`，发/收循环立刻停），已结束 → 删除该条记录；
- **清空会话**（`/api/history/clear`）同时清掉该会话的传输记录；"清空全部"清全部记录；
- 每端最多保留 200 条；记录写 `lanshare_transfers.jsonl`（Windows 在 dataDir、移动端在 filesDir），**重启后还在**；
  上次没传完的（status=active）启动时改成 failed/`interrupted`，不会留一条永远不动的进度；
- `GET /api/transfer` 每条带 `status/peer/xid/started/ended`，Windows 另给 `avg`（终态 = total/耗时）。

## 六、数据与目录

| 端 | 程序数据（不可被"清理目录"带走） | 用户文件 |
|---|---|---|
| Windows | `%TM%\plugins\LanShare\`：`lanshare_devices[.<inst>].json`、`lanshare_convs[.<inst>].json`、`lanshare_history.jsonl`、`lanshare_transfers.jsonl`、`lanshare.<inst>.lock`、`lanshare.log`；配置 `plugins\lanshare.ini` | `saveDir`（默认系统"下载"）`\<设备名>-<deviceId>\` |
| 鸿蒙 | `<filesDir>/`：`lanshare_devices.json`、`lanshare_convs.json`、`lanshare_history.jsonl`、`lanshare_transfers.jsonl`、`lanshare_settings.json` | `<filesDir>/save/<设备名>-<deviceId>/` |
| Android | `<filesDir>/`：同上 | `<filesDir>/save/<设备名>-<deviceId>/` |

- 设备目录名 = `<设备名>-<deviceId>`；改名后按 `-<deviceId>` 后缀沿用旧目录（否则旧文件"消失"）。
- 移动端设置只有**一个文件、一个写入者**（`lanshare_settings.json`，字段见 `Settings.ets` / `Settings.kt`）。
  历史上鸿蒙有两个写入者互相覆盖，导致"关掉的接收重启又变回开"——已修，别再加第二个写入者。
- 换默认目录必须带迁移，验收标准 = 迁移前后 `deviceId` **逐字符相同**。

## 七、协议硬约定（改代码前必读）

1. **TCP 监听用 `SO_EXCLUSIVEADDRUSE`，UDP 发现用 `SO_REUSEADDR`** —— 正好相反。
   TCP 用 `SO_REUSEADDR` 会让端口递进变成假象（两个进程同时 listen，连接被老进程接走）。
2. **端口以 announce/hello 报的值为准**，不许硬编码。
3. **未读只能由 `/api/messages/read` 清**；`GET /api/messages` 绝不清（"拉过" ≠ "看过"）。
4. **不排队、不 pending**：发送失败只有两种原因（不可达 / 对方关闭接收）；换 IP 只重试一次。
5. **清空只清本端记录，绝不删磁盘文件**；只有"删除设备"才清目录，且必须先 `dry=1`。
6. **内容相同只留一份**（尺寸 + 64 位哈希）；同名不同内容才加 `(2)`。
7. **删除设备不是拉黑**：只压制自动发现 60 秒；消息入站与手动添加照旧。
8. **`ini` 必须按 UTF-16 读写**：`dir=E:\临时` 用 UTF-8 存进去会被按 GBK 读成乱码且不报错。
9. **同一判据只能有一处实现**：脚本按名字判、产品按 `IfType` 判 = 假绿灯来源。
10. **失败要响亮**：静默失败（回 `ok:true` 却没生效）是本项目最主要的 bug 形态，`catch` 不许空着。

## 八、安全边界

- **无鉴权、无加密**：同一 Wi-Fi 下知道 `IP:port` 就能读消息和文件。不要在公共 Wi-Fi 开。
- 路由器开「AP 隔离」时互相看不见 → 用手动填 IP 兜底。
- 防火墙只做三件事：如实回报、加缺失规则、记住"不再提示"。**不静默加规则、不尝试提权。**

## 九、兼容与版本

| 字段 | 含义 |
|---|---|
| `apiVersion` | 当前 `"2"`。缺失或 `"1"` 视为旧端，按 legacy 通道 |
| `resumable` | 支持分片/续传；缺失 = 只能整份上传 |
| `platform` | 缺失记为 `windows` |

新增字段一律**纯增量**：老客户端忽略未知字段，新客户端对缺失字段取默认值。
